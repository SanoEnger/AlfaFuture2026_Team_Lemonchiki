# ФинМаршрут

Платформа кредитования бизнеса. React + TypeScript + Vite + Mantine, FastAPI, PostgreSQL. Оформление Graphite Glow и Pearl Light, IBM Plex Sans, Expandable Icon Rail и Hybrid AI Assistant 2.0.

## Запуск

Из корня проекта:

```powershell
python scripts/setup_env.py
docker compose up --build -d --wait
```

Приложение: http://localhost:5173. API: http://localhost:8000/docs. Письма при локальном запуске: http://localhost:8025 (Mailpit). Внешним адресатам Mailpit письма не доставляет; для доставки настройте SMTP_HOST, SMTP_PORT, SMTP_USERNAME, SMTP_PASSWORD, SMTP_STARTTLS и MAIL_FROM в .env.

При первом запуске создайте администратора через серверную команду:

```powershell
docker compose exec api python -m app.manage create-admin
```

Команда запросит email и пароль, если они не заданы переменными окружения; пароль не отображается. Повторное создание администратора запрещено. Клиенты регистрируются на странице входа и подтверждают email по ссылке в письме. Сотрудников приглашает администратор через кабинет. Выбор роли при входе отсутствует.

Порядок создания клиента: «Создать кабинет» → имя, email и пароль → подтверждение по ссылке из письма → вход → настройка компании. Вход и настройка компании не создают кредитную заявку.

Новый пароль должен содержать от 10 до 24 символов, включая буквы и цифры. Это правило применяется к регистрации, активации сотрудника, восстановлению, смене пароля и первичному созданию администратора. Вход с ранее установленным более длинным паролем сохраняется.

Порядок создания банкира: вход администратором → «Администрирование» → «Пригласить сотрудника» → email сотрудника → открыть письмо на http://localhost:8025 → перейти по приглашению → указать имя и пароль сотрудника → выйти из аккаунта администратора → войти с email и паролем сотрудника. Банковская роль назначается автоматически по приглашению. Обычная регистрация создаёт только клиента.

## Данные и кредитный процесс

Все компании, заявки, финансовые показатели, решения, назначения сотрудников, история и метаданные документов сохраняются в PostgreSQL. PDF хранятся в постоянном томе documents. В браузере остаются настройки оформления и идентификатор текущего черновика; авторизация использует HttpOnly cookie, команды защищены CSRF.

Компания → черновик → отправка → проверки → рассмотрение → запрос уточнений / предложение / отказ. Сотрудник берёт свободную заявку в работу; кредитные команды разрешены назначенному сотруднику. Администратор управляет доступом и назначениями. Клиент принимает или отклоняет предложение, затем завершает оформление.

При рассмотрении доступны отдельные действия «Одобрить на условиях клиента» и «Предложить другие условия». Одобрение сохраняет запрошенные сумму и срок, ставку берёт из выбранного продукта и показывает её перед подтверждением. Встречные условия сотрудник задаёт вручную. В обоих случаях клиент подтверждает банковское предложение в своём кабинете.

Подключения к внешнему реестру и БКИ нет. Проверяется формат сохранённых реквизитов, отсутствие подтверждений отражается в результатах и консервативной оценке риска. Решение принимает сотрудник. Статус «Завершена» фиксирует оформление заявки; денежные перечисления отдельной платёжной системы не выполняются.

Обычный запуск создаёт только каталог продуктов и материалы для бизнеса. Аккаунты и заявки автоматически не создаются. Существующие таблицы, идентификаторы и тома сохранены. Миграция 0002 добавляет серверные аккаунты, сеансы, одноразовые токены, аудит, назначения, комментарии и ревизии. Перед обновлением существующей БД сохраните резервную копию.

## Настройки

Секреты .env создаёт scripts/setup_env.py; файл исключён из Git. PUBLIC_APP_URL должен совпадать с адресом приложения, чтобы ссылки в письмах вели на нужный сайт. При изменении порта обновите CORS_ORIGINS. Для HTTPS установите SESSION_COOKIE_SECURE=true. Длительность сеанса: 30 минут простоя, максимум 12 часов.

Название и подзаголовок задаются в frontend/shared/brand.ts. Знак платформы: frontend/public/favicon.svg. Внутренние имена контейнеров и БД сохранены для совместимости.

## Проверки

```powershell
cd frontend
npm.cmd ci
npm.cmd run build
npm.cmd test
npm.cmd run test:e2e
cd ..
docker compose --profile test run --rm tests
```

Браузерные проверки запускают отдельный API с изолированной SQLite-базой и не используют рабочую БД. Последняя команда проверяет настоящий PostgreSQL в отдельных временных схемах, включая миграции и конкурентные операции.

## Структура проекта

- `frontend/` — интерфейс, оформление и браузерные тесты.
- `backend/` — API, бизнес-логика, миграции и серверные тесты.
- `docs/architecture.md` — устройство приложения.
- `docs/specs/` — технические задания.
- `docs/frontend-reference/` — исходные визуальные макеты.
- `scripts/` — настройка окружения и проверка запуска.

Основное ТЗ: [SMART_CREDIT_MASTER_SPEC.md](docs/specs/SMART_CREDIT_MASTER_SPEC.md). Контракт API: [backend/openapi.json](backend/openapi.json).

PostgreSQL доступен только сервисам внутренней сети Docker. Для консоли БД: `docker compose exec db psql -U alfa -d alfa`.

Mailpit: [официальная документация контейнера](https://mailpit.axllent.org/docs/install/docker/).
