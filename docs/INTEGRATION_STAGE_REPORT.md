# Дополнительный этап — интеграция после frontend двух ТЗ

Дата: 24.10.2026. Начат строго после завершения первого файла, frontend второго файла, 33 unit-тестов, 21 функционального E2E и отдельной визуальной проверки новых экранов.

## Реализованный объём

Отдельный `/server-login` использует действующий учебный Bearer API. Роль и пользователь определяются `/auth/me`; при перезагрузке приложение сначала проверяет сеанс и каталог, затем показывает защищённые страницы. JWT хранится в sessionStorage вкладки, удаляется при выходе и 401. Это совместимость с существующим API, не реализация целевых cookie-сессий.

`shared/api/data.ts` явно выбирает автономный либо серверный адаптер. Серверные ошибки не приводят к подстановке локального seed. В API-режиме продукты имеют реальные UUID и лимиты сервера; заявки, профиль компании, документы, запросы, история, предложения и скоринг загружаются из API. Помощник остаётся локальным FAQ, но читает разрешённые сервером данные через тот же адаптер. Финансовые значения API-формы не записываются в localStorage; для продолжения хранится только ID серверного черновика в sessionStorage.

Работают сохранение/отправка, ответ банку новым PDF, загрузка и авторизованное скачивание файла, предложение и отказ, принятие/отклонение, явное завершение после ACCEPTED. Колонки сравнения используют исходный запрос и отдельный оффер.

## Дополнения API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/auth/me` | Безопасная текущая учётная запись и роль |
| GET | `/api/v1/catalog` | Общий каталог для авторизованных ролей; прежний CLIENT-only `/products` сохранён |
| PATCH | `/api/v1/business/me` | Реквизиты и финансовые данные текущей компании |
| GET | `/api/v1/applications/{id}/documents` | Файлы собственной заявки |
| GET | `/api/v1/applications/{id}/information-requests` | Запросы банка по собственной заявке |
| GET | `/api/v1/applications/{id}/documents/{document_id}/download` | Скачивание с проверкой владельца заявки и связи файла |
| POST | `/api/v1/applications/{id}/complete` | Явное завершение демонстрации после ACCEPTED |

Для `/accept` добавлен `complete_demo=false`: новый UI получает ACCEPTED и завершает процесс отдельно. Значение по умолчанию сохраняет старое поведение API, чтобы не сломать существующие тесты, smoke и внешних клиентов. Финальная операция не означает перечисление средств.

Представление отправленной заявки читает сохранённый financial_snapshot вместо подмены его новыми финансами компании. В новые snapshots добавлены legal_name и form. Legacy snapshots с отсутствующими либо null-полями не ломают сериализацию; неизвестное историческое название не восстанавливается искусственно.

## OpenAPI и типы

`backend/openapi.json` обновлён из FastAPI. `frontend/scripts/generate-api-types.py` генерирует `shared/api/generated.ts` (30 схем); ручной wire-контракт не поддерживается параллельно. Команда: `npm.cmd run generate:api`. Нормализация в серверном адаптере переводит wire DTO в существующую view model, сохраняя десятичные строки.

## БД и окружение

Существующая схема не изменена. ORM, Alembic-миграции и пользовательские таблицы не пересоздавались. Миграций не добавлено: новые endpoints используют существующие сущности, дополнение snapshot хранится в существующем JSON-поле.

Docker Engine не запущен. Обнаружена локальная служба PostgreSQL 18, но проверенное подключение к отдельной тестовой БД не настроено; в среде дополнительной проверки отсутствовал драйвер psycopg. Подключение и применение изменений к рабочей PostgreSQL не выполнялись. Проверки PostgreSQL не объявляются пройденными.

HTTP E2E запускает отдельный FastAPI на 8011 и Vite на 5174. Для каждого запуска создаётся новая синтетическая SQLite и каталог файлов внутри `.local/api-ui-*`. Рабочая БД не затрагивается. Проверено сохранение после перезагрузки браузера, но не после перезапуска PostgreSQL/API.

## Серверные функции, которые остаются за пределами этой интеграции

- Регистрация, подтверждение email, восстановление пароля, приглашения и BANK_ADMIN — только в автономном UI. Существующий сервер не имеет нужных сущностей/маршрутов; заглушки не выдаются за реализацию.
- Настоящий первоначальный CLI администратора, cookie/HttpOnly/CSRF, rate limiting, отзыв серверных сессий и безопасная смена email/пароля.
- Серверные назначения/claim/reassign, расширение роли BANK_OFFICER/BANK_ADMIN и соответствующая авторизация. В API-режиме назначение явно недоступно; legacy сервер продолжает проверять CLIENT/BANK_EMPLOYEE.
- Серверные expected-version проверки PATCH и межпроцессная идемпотентность. Существующее version связано с попыткой проверок, поэтому оно не было молча перепрофилировано под optimistic locking.
- Серверная пагинация, сохранённые AI-диалоги, полноценный OpenAPI-generated endpoint client (генерируются схемы, вызовы типизированы адаптером).
- Полный master DoD: PostgreSQL, реальные письма, server security, конкурентный claim и сохранение после перезапуска всех сервисов ещё не подтверждены.

Эти пункты требуют отдельного серверного этапа с безопасными миграциями из MASTER_GAP_AUDIT.md. Они перечислены как оставшиеся, а не как готовые.
