# Этап 2 — frontend SMART_CREDIT_MASTER_SPEC

Этот отчёт фиксирует состояние на момент завершения frontend-этапа. Последующая дополнительная интеграция описана в [INTEGRATION_STAGE_REPORT.md](INTEGRATION_STAGE_REPORT.md).

Выполнен после первого файла, до любых подключений к серверу или БД. Основной объём — автономный frontend, как первоначально поручено пользователем. Разрешение на необходимую интеграцию получено отдельно, строго после этого этапа.

## Совместимость

Сохранён legacy BANK_EMPLOYEE для исходных сценариев. Добавлены BANK_OFFICER и BANK_ADMIN в frontend-модель. /login больше не предлагает назначить банковскую роль; фиксированные учебные роли доступны отдельно в /demo-login. Новые публичные пути, onboarding и administration добавлены к существующим маршрутам, а не заменяют кредитные страницы.

## Серверные требования, не являющиеся frontend-реализацией

Открытый локальный demo mailbox, localStorage и PBKDF2 в браузере служат только проверке UI на синтетических данных. Это не серверная авторизация, не реальная почта, не защищённое хранилище и не доказательство PostgreSQL persistence. Реальные cookie/CSRF, rate limiting, первоначальный CLI администратора, membership enforcement, серверный отзыв сеансов, межпроцессный claim и транзакционная идемпотентность остаются отдельными требованиями интеграции. Карта текущей ORM и пробелов — MASTER_GAP_AUDIT.md. Полный Definition of Done всей серверной системы нельзя объявить выполненным только по этим frontend-проверкам.
