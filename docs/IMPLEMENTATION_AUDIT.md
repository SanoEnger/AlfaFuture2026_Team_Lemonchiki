# Аудит первого этапа

Источник: CODEX_IMPROVEMENTS_PLAN.md, 23.10.2026.

## Архитектура и действующие контракты

Frontend: React 19, TypeScript, Vite, Mantine 8, React Router, TanStack Query. Маршруты `/client/*`, `/bank/applications`, `/bank/applications/:id`, `/bank/settings`; роли CLIENT / BANK_EMPLOYEE проверяет Guard. Серверное REST API описано в backend/docs/api_contract.md: `/api/v1`, десятичные строки денежных значений, состояния DRAFT → SUBMITTED → VERIFYING → UNDER_REVIEW, запрос NEEDS_INFO с resubmit, OFFERED с accept/decline. Контракт изучен только для совместимости.

Пользователь явно ограничил работу автономным фронтендом: сервер и БД не подключаются и не изменяются. Запросы ТЗ на серверные переходы выполняются только как локальная UI-симуляция в shared/api/demo.ts. Это ограничение приоритетнее вложенного документа. Настоящие серверные проверки, авторизация и загрузка файлов вне объёма.

## Что уже работает

Две темы с общей геометрией, локальные шрифты, Icon Rail 68/224, закрепление и мобильное меню, помощник 420/580 с контекстом и раздельными историями, маршруты ролей, мастер из четырёх шагов, сохранение демоданных, PDF-проверка, запросы банка, предложения, история, риск с объяснениями, настройки темы/плотности/движения, модульные и браузерные проверки.

## Изменения первого этапа

ACT-01: чистая deriveNextAction и общий NextActionPanel на главной и в карточке.
ROLE-01: отдельная закреплённая BankDecisionBar; сохранены банковские вкладки.
FORM-01: подтверждённое автосохранение с debounce, очередью, версией, повтором и восстановлением черновика; полевая валидация.
DOC-01: DocumentChecklist, dropzone, повтор загрузки, честные состояния без вымышленных статусов проверки.
OFFER-01: общий OfferComparison с акцентом на изменившиеся параметры.
AI-01: сворачиваемые вопросы после первого сообщения.
DATA/UX/THEME/A11Y/DENSITY/POLISH: единые состояния, плотность по роли, числовые колонки и адаптивность в существующих компонентах.

Новые файлы находятся внутри существующих features, components/ui и src/styles; параллельный каркас приложения не создаётся.

## Риски регрессий

Сохранение старого черновика поверх новых значений, потеря идентификатора при перезагрузке, двойные клики, устаревшие операции после смены статуса, смешение исходных и предложенных условий, переполнение таблиц при открытом помощнике. Проверяются модульными тестами и сквозными сценариями, в том числе на 390/768/1280/1440 px и в обеих темах.
