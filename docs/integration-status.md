# Проверка интеграции 23 октября 2026 года

## Выполнено Волосниковым

- Локальные MockRegistry/MockBKI с явными синтетическими записями, проверкой названия и обработкой неизвестных данных.
- ScoringService `volosnikov-rules-v1`: Decimal, аннуитетный платёж, 4 объяснимых компонента и LOW/MEDIUM/HIGH.
- Подключение через существующие Protocol без изменений ORM и миграций Смирнова.
- Dockerfile, Compose для PostgreSQL, миграций, сидов, API, PDF volume и отдельных тестовых сервисов.
- Генерация локальных секретов, healthcheck, HTTP smoke и автоматизированная проверка перезапуска.
- Архитектурная схема, описание правил, запуск, зависимости и лицензии.

## Подтверждено

- 30 новых тестов модулей риска и совместимости с сидами проходят, включая пороги MEDIUM/50 и LOW/75.
- Все 10 существующих тестов workflow/API проходят с новым скорингом и каноническими моделями на SQLite.
- HTTP smoke через отдельный процесс API: успех, уточнение с PDF и контроффером, отказ, отклонение предложения, 403/404/409/422, персонализация новостей.
- Повторное чтение заявок, истории и точного содержимого PDF после остановки и запуска API на отдельной временной SQLite БД. Пользовательская `backend/demo.db` не изменялась.
- Конфигурация `docker compose config --quiet` проходит; Python-файлы компилируются; `pip check` не обнаруживает нарушенных зависимостей.
- Alembic успешно генерирует SQL миграции `0001` для PostgreSQL в offline-режиме; это не проверка выполнения SQL сервером.

## Требует завершения

Docker Desktop на компьютере завершился с внутренней ошибкой при инициализации Inference manager (`dockerInference`). Сборка образа, запуск PostgreSQL, тесты PostgreSQL и сохранность данных после перезапуска контейнеров в этой сессии не подтверждены. SQLite-проверки не заменяют их. После восстановления Docker выполнить из корня:

```powershell
python scripts/verify_stack.py
```

React-интерфейс отсутствует в репозитории. После его добавления: включить frontend в Compose, проверить все AT-01…AT-12 в браузере и оформить Playwright smoke. Подбор продукта по цели и состав клиентской карточки уточнения остаются задачами согласования frontend/backend. Реальный релизный тег и точный commit сдачи фиксируются после успешной общей приёмки; тег сейчас не создан.
